How it works

We analyze domain, content, link, and live behavior signals (redirects, timers, consent dialogs) and show grouped reasons you can verify. Results are designed to be explainable and fast for everyday use.

What simple “checkers” typically do

  • Rely mainly on blocklists / static reputation.
  • Little or no browser behavior simulation.
  • Opaque scores without analyst-friendly reasons.
  • Heavy data retention and privacy trade-offs.

What CheckThatURL does differently

  • Behavior-first inspection of redirects, timers, popups, consent.
  • Explainable verdicts grouped by signal class.
  • Zero-retention default with self-hosted option.
  • SIEM-ready outcomes and exportable evidence.

Under the hood — how a verdict is produced

1) Signal Collection

Domain, content, link graph, and live behavior signals. Optional intel connectors per tenant.

2) Behavioral Simulation

Headless browser follows redirects, detects timers/popups, records consent clicks.

3) Hybrid Fusion

Heuristics + ML + LLM-assisted rationale reduce noise and highlight attacker intent.

4) Explainable Output

Verdict + grouped reasons + evidence, ready for analyst review and SIEM forwarding.

Docs & Quickstart

REST API

Quickstart: POST /check

Send a URL for analysis. Optional quick=1 for faster heuristics.

POST https://checkthaturl.com/check?ui=redacted
Content-Type: application/json

{"url":"https://example.test/login"}

Response (truncated):

{
  "verdict": "Suspicious",
  "risk": 0.72,
  "explanation": "Multiple redirects and consent-capture pattern",
  "domain_risks": [...],
  "behavior": { "redirect_chain": [...], "clicks": 1 }
}
